## 2026-06-08 — Session 4: Bug fixes — save/exit cleanup, loot despawn

### Bug Fixes

**Save and Exit — pause menu overlay persisted on main menu**
- `_on_save_and_exit()` was calling `change_scene_to_file()` without freeing the
  PauseMenu CanvasLayer first. Root-level nodes survive scene changes.
- Fix: added `queue_free()` before `change_scene_to_file()` in pause_menu.gd.

**Save and Exit — HUD (chat, action bar, frames) persisted on main menu**
- player_frame, target_frame, game_log_window, action_bar are all added to scene root
  in _spawn_hud() and survive `change_scene_to_file()`.
- Fix: all HUD nodes now tagged with group `"game_hud"` on spawn. `_on_save_and_exit()`
  iterates the group and queue_frees every node before changing scene.

**Monster — lootable infinitely after being looted**
- `corpse_loot_window.setup()` called `loot.duplicate(true)`, giving the window its own
  copy. Items taken from the window never depleted the monster's `pending_loot`, so
  `is_lootable` stayed true and the window could be reopened with full loot each time.
- Fix: removed `.duplicate(true)` — the window now holds a direct reference to the
  monster's array. `_take()` / `_loot_all()` mutate it in place.
- Added `signal all_looted` to corpse_loot_window, emitted when `_rebuild_list()` finds
  the array empty. `open_loot_window()` connects this to `_on_fully_looted()` which sets
  `is_lootable = false` and despawns the corpse after 5 seconds.
- Added `if not is_inside_tree(): return` guard in `die()`'s 60s auto-despawn await so
  it safely exits if the corpse was already freed via the loot path.

## 2026-06-08 — Session 2: Combat fixes, HUD improvements, action bar

### Bug Fixes

**combatnode.gd — `class_name` reserved keyword crash**
- `func set_class(class_name: String)` used a GDScript reserved keyword as a parameter.
- Renamed parameter to `new_class`. Game was unlaunchable until this fix.

**player_frame.gd — `get()` too many arguments**
- `_player.get("current_stamina", 0.0)` — GDScript's Object.get() takes 1 arg, not 2.
- Changed to ternary `_player.get("x") if "x" in _player else default`.

**combatnode.gd — ATK stat double-counted in damage**
- `calculate_melee_damage()` added `get_atk()` to raw damage.
- ATK is a hit-accuracy stat used in `calculate_hit_chance()`, not a damage bonus.
- Monsters had `gear_atk = 40 + level×10`; a level-2 skeleton was dealing 60+ base damage.
- Fix: removed `get_atk()` from damage formula. Damage is now `weapon_damage + str/2`.

**monster3d.gd — monster hit rate too high**
- `gear_atk = 40 + level×10` gave skeleton ~95% hit rate vs player AC 14.
- Changed to `gear_atk = 15 + level×5` (level-2 skeleton now ~55-60% hit rate).

**project.godot — A/D keys mapped to ui_left/ui_right**
- Caused TabContainer in game_log_window to switch tabs while strafing.
- Removed physical_keycode 65 (A) from ui_left and 68 (D) from ui_right.
- Arrow keys remain bound; A/D now only fire player movement actions.

**camera_controller.gd — mouse_mode conflict with Alt toggle**
- Removed Alt-key mouse toggle (unreliable).
- Replaced with right-click-hold for mouse look: MOUSE_MODE_CAPTURED while held,
  MOUSE_MODE_VISIBLE on release. Default mode is now VISIBLE (cursor free).

## 2026-06-08 — Godot Startup Crash Fix

### Problem
Game crashed on startup with:
  Error at (36, 16): Could not parse global class "CombatNode" from "res://Scripts/combatnode-OLD.gd"

### Root Cause
.godot/uid_cache.bin contained stale UID entries for scripts that had been deleted
from the Scripts/ directory (backpack_ui-OLD.gd, character_creation-OLD.gd,
inventory-OLD.gd). Godot tried to resolve these UIDs on startup and failed.

### Fix
Deleted stale cache files and let Godot rebuild them on next launch:
  - .godot/uid_cache.bin
  - .godot/global_script_class_cache.cfg

### Also
Committed archive-2d/ directory to git as a versioned backup of deprecated 2D
scripts and scenes (combatnode-OLD, mob-OLD, player-OLD, backpack_ui-OLD, etc.).
