how to rig a new character model:
(see chat for the full walkthrough — short version below)
-download/build the base mesh (Meshy or similar), export as FBX
-go to mixamo.com, upload the FBX to auto-rig it (needs a T/A-pose; only accepts .fbx/.obj, not .glb — export as FBX first if needed)
-download the rigged character itself once "With Skin" — this is the base model file
-download every other animation you want (idle/walk/run/jump/sit/attack/death/etc.) "Without Skin" (motion-only, much smaller, retargets onto the skin you already have)
-drop everything for one character into its own folder under models/<Character Name>/ (matches the Human Female / Human Male / Troll Male pattern)
-tell Claude the folder's ready — it needs one editor import pass (headless, automatic) then builds a merged AnimationLibrary + wires the race/sex into player3d.gd's CHARACTER_MODELS the same way as the last three
-texture note: don't bother fighting Blender's FBX export to embed the texture — it's been unreliable every time. Just make sure the real texture PNG is sitting in the same folder as the FBX; the game applies it directly as a runtime material override instead of depending on the FBX carrying it
-if you want a second attack animation, look for something like "Standing Melee Attack Downward" in Mixamo in addition to "Standing Melee Attack Horizontal" (or vice versa) — that's the pair the male model uses for its two random swings

● Here's the process for animating Oni, based on how your current models are wired.

  Why your usual pipeline won't work for her: Mixamo auto-rigs and animates humanoids only. A cat has to be animated by hand in Blender.
  Everything else in your pipeline stays the same.

  In Blender:
  1. One armature, skinned mesh. The mesh parents to the armature with weights (automatic weights are fine, then check the joints). Keep to 4 or
     fewer bone influences per vertex, and apply scale and rotation (Ctrl+A) so both are 1.
  2. Origin and orientation. The model should stand on the ground at the origin, facing forward. I can auto-ground her height in Godot
     (CatModel.ground_and_measure already does this), but a clean origin saves tweaking.
  3. Actions: one per animation, named in lowercase exactly like your existing libraries. Use idle, walk, run, attack and death. Idle, walk and
     run should loop, so make the first and last frames match. Attack and death play once, and death should hold its last pose.
  4. Save the actions. Give each Action a fake user (the shield icon), or the exporter will skip it.
  5. Export as glTF 2.0 (.glb) with animation set to "all actions" (not just the active one). glTF keeps clip names reliably, which matters
     here. FBX also works, but only if you turn on export of all actions.
  6. Textures: keep the Meshy texture PNG next to the export. Godot loses FBX texture links, so I apply it as an override, like your other
     models.

  Then to me:
  1. Drop the export into models/Oni/ and tell me. I'll run the import, check that the skeleton and clip names came through, and build an
     animation library (oni_animations.res), like the ones for your other characters.
  2. I'll swap her cat visual to the animated model and hook it to what she already does: idle when standing, walk on patrol, run when chasing a
     rat, attack on the pounce, death on death. Her pouncing code currently fakes it with a procedural bob, and that gets replaced.

  For Kenji and the non-human mobs, it's the same recipe. Each mob needs the same five clips, and in the game each species is one entry (scene,
  animation library, texture) in a table in monster3d.gd. Do Oni first as the template. Once we've proven the export settings work, each new
  creature is just export, drop in the folder, and I wire it.

  Do a first quick test with just idle and walk before you animate everything. That way we find any export problems early.

tools/update.sh --reboot-in 5

  Run it from the repo on your PC, not on the VM. The ~/update.sh on the VM is your apt-upgrade script.
  1. Upload: it exports and uploads as usual. The running server is untouched, because the new binary goes up under a temporary name.
  2. Announce: it then tells the server, which immediately shows the red centre-screen message and puts it in chat. New logins are refused, and
     reminders come at 3 minutes, 1 minute, 30 s and 10 s.
  3. Go down: the server saves everyone and exits the moment the last player logs out, or at 5 minutes. If nobody is on, it goes down at once.
     The script waits for it to exit (up to 8 minutes).
  4. Restart: nothing restarts it. Your terminal just returns to the prompt. For an automatic restart add --restart, for example:
     tools/update.sh --reboot-in 5 --restart 'tmux kill-session -t game 2>/dev/null; tmux new-session -d -s game "$HOME/run_aldenexia.sh"'
     The new server then runs in a tmux session called game, which you can view with tmux attach -t game. I haven't tried that restart command
     against your real server, so try it once when you're watching.
